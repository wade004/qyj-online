# 《群英决》手机 H5 设计方案

> 文档状态：方案评审稿 v1.2（横屏专用、PC 零回归）<br>
> 日期：2026-07-11<br>
> 适用范围：当前版本的模式选择、单机选将、联机大厅/队伍/选将、六人对局、技能、战报与结算<br>
> 本期原则：不改玩法规则，不新增社交玩法，完成可正式上线的移动端重构

> 实施状态（2026-07-11）：独立 H5 入口、横屏门禁、全流程横屏 UI、移动 WebP、共享会话层、90 秒短时恢复、PC/H5 混合端自动化均已落地。物理 iOS/Android 真机兼容与灰度发布仍属于部署前人工验收，不以桌面浏览器视口模拟替代。

## 1. 结论先行

当前版本不能通过“整体缩小”或补几个媒体查询变成手机 H5。建议采用以下产品与技术路线：

1. 首页、大厅、房间、选将、战斗和结算全部采用横屏专用布局，不交付竖屏功能页面。
2. H5 启动后先进入横屏门禁；竖屏只显示不可操作的旋转引导层，禁止进入游戏功能。
3. 用户点击“横屏进入游戏”后，客户端尝试进入全屏并锁定 landscape；浏览器不支持方向锁时，等待用户手动旋转。
4. 战报、AI 建议、英雄详情、技能说明和边池明细改为按需抽屉，不再常驻挤占战场。
5. 联机上线前补齐会话恢复、服务端时钟、命令幂等和弱网反馈。
6. 立绘、背景和音频建立移动资源管线，首屏不再一次加载全部大图和 BGM。

本期上线的三个硬前置是：

- 移动战斗 HUD 重构；
- 可恢复联机会话；
- 移动图片/音频资源管线。

其中任意一项缺失，都不建议以正式版本发布。

### 1.1 PC 共存不可妥协项

- PC 继续使用稳定入口 /index.html；H5 使用独立入口 /h5.html 或 /m/，不得根据窗口宽度自动替换平台。
- PC 与 H5 共享游戏规则、协议和无界面会话状态；DOM、CSS、交互和方向控制分别实现。
- H5 的全屏、方向锁与竖屏阻断模块不得被 PC 入口导入。
- H5 样式不得追加进现有全局 style.css；PC 使用 pc-* 命名空间，H5 使用 h5-* 命名空间。
- 不允许在共享 battle.js / online.js 中堆叠 isMobile 条件；先抽离无界面控制器，再由 PC/H5 视图订阅同一状态。
- 每次 H5 改动都必须通过 PC 视觉基线、PC 完整流程和 PC/H5 混合房对局；任一失败均不得合并。
- PC v2 与 H5 使用独立功能开关和发布开关，任何一端异常都可单独回滚。

## 2. 当前版本审计结论

### 2.1 已有完整功能

当前版本不是单页展示，而是一套完整游戏：

- 首页：单机人机、联机组队；
- 单机：16 英雄选将、1 真人 + 5 AI、12 回合对局、结算；
- 联机：连接、大厅、创建/加入队伍、改名、离队、房主开局、互斥选将、AI 补位、战后回房；
- 战斗：六人座位、暗令、五张公共牌、血祭、主池/边池、六类行动、主动/被动技能、胜算、AI 建议、战报、计时与延时、阵亡和最终排名。

手机版本必须保留上述规则能力，只重排信息和交互。

### 2.2 当前上线阻断

- 五张公共牌固定宽度约 728px；整个底部操作组合实际需要约 1286px 宽。
- 桌面内容纵向约 879px，且页面全局禁止滚动，手机会直接裁掉而不是自适应。
- 现有响应式断点只覆盖选将网格，战斗、联机页面、结算和弹层没有移动布局。
- 缺少 viewport-fit=cover、100dvh、安全区、横屏门禁、方向锁降级和软键盘处理。
- 声音、延时、复选框等多个热区小于 44×44px，且大量反馈依赖 hover。
- 结算、技能选择和战报在短屏没有最大高度与独立滚动。
- 16 张选将立绘合计约 29.3MB，解码内存约 156MiB；全资源约 84.6MB。
- 联机断开后，服务端删除客户端身份；若恰好轮到该座位，约 1 秒后自动静观或退避，客户端无法回到原座位。
- 玩家名、队伍名和服务端消息存在直接拼接进 innerHTML 的路径，生产前必须统一改为安全文本渲染。

## 3. 设计目标与边界

### 3.1 核心目标

- 关键决策 1 秒内可识别，正常行动 2 次点击内完成。
- 六个合法行动位置固定，不能因状态变化而跳动。
- 五张公共牌、两张本人暗令、倒计时和所有行动无需页面滚动即可看到。
- 任何竖屏尺寸都不得渲染可操作的游戏页面。
- 断网、刷新或网络切换后，在保留期内可恢复原座位和本人暗令。
- 中端手机、普通 4G 下首屏可用，不因立绘解码造成白屏或页面被系统回收。
- 刘海、圆角、浏览器地址栏和 Home Indicator 不遮挡任何操作。

### 3.2 本期不做

以下能力有产品价值，但不属于“当前版本手机化”的上线范围：

- 快速匹配、邀请码、准备状态；
- 分享战绩、社交关系、聊天；
- 新英雄、新技能、新下注档位；
- 复杂战绩统计和成长系统。

这些可进入后续功能版本，不应拖慢本期移动重构。

## 4. 平台、方向与画布

### 4.1 支持策略

- iOS Safari、Android Chrome、主流内置 WebView/微信浏览器最近两个主要版本；
- 标准横屏完整保障：667×375 及以上；
- 568×320 至 666×374 进入紧凑横屏模式，减少装饰和说明，但不删除任何功能；
- 小于 568×320 的横屏视口显示“不支持当前屏幕尺寸”，不进入游戏；
- 竖屏视口只显示横屏门禁，不属于功能页面支持范围。

设计与验收画布至少包含：

- 568×320、667×375、740×360、812×375、844×390、915×412、932×430。

### 4.2 方向策略

- 全部功能页面只在 landscape 媒体条件成立时显示。
- 启动页提供“横屏进入游戏”按钮；点击后依次尝试 requestFullscreen 与 screen.orientation.lock('landscape')。
- 支持方向锁的浏览器自动切换；Safari/WebView 等未暴露或拒绝方向锁的环境显示旋转引导，用户手动横置后自动放行。
- 游戏中一旦变回竖屏，立即以最高层级旋转遮罩阻断全部游戏点击；恢复横屏后回到原状态。
- 单机在竖屏遮罩期间暂停本地引擎；联机不能暂停全局对局，遮罩必须提示“行动计时仍在继续”。
- 方向变化不重新创建引擎、不重新连接、不丢失技能选择草稿。

### 4.3 视口规范

- viewport 增加 viewport-fit=cover，保留用户缩放；
- 页面壳使用 100dvh，并提供 100vh/100svh 回退；
- 四边统一使用 env(safe-area-inset-*)；
- 首页、大厅、房间、选将和结算在横屏短高度下使用区域内滚动；战斗页面本身固定，抽屉和列表独立滚动；
- 输入框字号至少 16px，软键盘弹出时当前输入与提交按钮必须可见。

## 5. 信息架构与导航

~~~text
启动 / 横屏门禁 / 核心资源准备
├─ 首页（仅横屏）
│  ├─ 单机 → 选将 → 战斗 → 结算 → 再选英雄
│  └─ 联机 → 连接 → 大厅 → 队伍 → 选将 → 战斗 → 结算 → 返回队伍
└─ 未结束会话 → 继续对局 / 放弃并返回首页
~~~

导航规则：

- 首页返回：交给浏览器。
- 大厅返回：首页；队伍返回：二次确认后离队并回大厅。
- 选将返回：单机回首页；联机明确提示会退出队伍或回队伍，不能直接离站。
- 战斗返回：弹出“继续对局 / 退出并托管”，默认焦点在继续对局。
- 结算返回：单机回选将，联机回原队伍。
- 接管 popstate、visibilitychange 和 pagehide；页面刷新后优先尝试恢复联机会话。

## 6. 全局设计系统

### 6.1 视觉方向

延续现有“暗色鎏金国风”，但减少大面积金边、持续发光和厚重阴影。金色只用于品牌、主操作、当前行动者和胜负关键状态。

建议色板：

| 语义 | 色值 | 使用 |
|---|---:|---|
| 页面背景 | #0C0A08 | 全局底色 |
| 一级表面 | #18120D | 顶栏、操作坞 |
| 二级表面 | #241A12 | 卡片、抽屉 |
| 主金色 | #E7C66A | 主按钮、当前态 |
| 金色按下 | #C9A547 | pressed |
| 主文字 | #F7EFD9 | 正文/标题 |
| 次文字 | #B8AA8C | 辅助说明 |
| 危险 | #E2554F | 决死、断线、错误 |
| 成功 | #4CC27A | 已选、连接成功 |
| 能量 | #5CB6E8 | 能量与辅助信息 |
| 焦点 | #7EC8FF | focus-visible |

要求正文对比度不低于 4.5:1，大字及非文本控件不低于 3:1。

### 6.2 字体与间距

- 字体：PingFang SC、Noto Sans SC、Microsoft YaHei、系统无衬线；
- 品牌标题 28–36px；页面标题 20–24px；正文 14–16px；战斗辅助文字不小于 12px；
- 输入框最小 16px；数字使用 tabular-nums；
- 4/8/12/16/24px 间距体系；
- 普通圆角 8px，卡片/抽屉 12px；
- 交互热区最小 44×44px，主按钮高度 48–56px，相邻热区至少 8px。

### 6.3 动效

- 点击反馈 80–120ms，抽屉 180–240ms，发牌/获池不超过 600ms；
- 动画只改变 transform 与 opacity，避免 transition: all；
- 对局结果优先于演出，演出期间也能读到最终状态；
- prefers-reduced-motion 下关闭震屏、刀光、卡牌飞行和闪烁，保留淡入和文字结果；
- 页面后台暂停非必要 rAF、视觉模拟和音乐，恢复时立即向服务端校时。

## 7. 页面方案

### 7.1 启动与资源准备

结构：品牌标识、加载进度、当前资源说明、失败重试。

- 首次点击“横屏进入游戏”后请求全屏与方向锁；
- 当前仍为竖屏时只显示旋转手机示意、兼容说明和“重试横屏”，不得显示模式、房间或战斗控件；
- 首屏只加载页面壳、首页背景低清图和基础图标；
- 音频必须在用户首次点击后加载；
- 若存在可恢复联机会话，首屏主按钮为“继续对局”；
- 资源失败允许单项重试，不能整页白屏；
- 新版本可用时在安全节点提示更新，对局中不强制刷新。

### 7.2 首页 / 模式选择

横屏结构：

- 左侧约 45%：品牌、短标语、低对比英雄背景；
- 右侧约 55%：两个 56px 高模式卡——“单机·人机对战”“联机·组队对战”；
- 右下：规则入口、设置、版本号和服务器状态；
- 声音入口并入设置，不再悬浮在刘海区域。

联机不可用时按钮仍可点击，进入可恢复的错误页；不要只显示灰色且无解释。

### 7.3 联机连接页

状态包括：连接中、连接失败、重连中、服务器维护、版本不兼容。

每种状态必须有：状态标题、简短原因、主动作、次动作。

- 连接失败：重试 / 返回首页；
- 重连中：保持当前页面和状态，显示第几次尝试；
- 版本不兼容：刷新更新；
- 无网络：监听网络恢复并自动重试。

### 7.4 组队大厅

- 48px 顶栏：返回、标题、连接状态、刷新；
- 队伍使用整行卡片：队名、人数、待命/选将中/对局中、加入按钮；
- 只允许可加入队伍进入，满员与进行中给出文字原因；
- 列表可滚动，底部固定“创建队伍”；
- 空态、加载态、错误态分别设计；
- 下拉刷新可作为增强，但必须保留可见刷新按钮。

### 7.5 队伍房间

- 顶部：队名、人数、房主标识；
- 中部：最多三个真人席位，显示本人、房主、在线/弱网/离线；空位显示 AI 补位说明；
- 改名进入个人资料抽屉，避免与开始按钮挤在同一行；
- 房主底部主按钮：“开始选将”；成员显示“等待房主开始”；
- 次按钮：“退出队伍”，点击后二次确认；
- 战后返回时保留队伍成员与房主关系。

### 7.6 英雄选择

手机列表不再在每张卡上展示完整技能正文。

- 顶栏：返回、选将标题、倒计时和队友已选摘要；
- 左侧 56%：英雄网格；标准横屏 3–4 列，紧凑横屏 2 列；卡片只展示缩略立绘、姓名、类型、主动技名和费用；
- 右侧 44%：当前英雄详情，展示立绘、主动效果、条件、被动、台词和确认按钮；
- 详情区底部明确“选择该英雄”；单机选择后再确认开战，不再点卡即开局；
- 联机由服务端确认后显示“已选，可换”，并标注占用者；
- 被占用状态同时使用锁图标、文字和降噪，不只降低透明度；
- 最后 10 秒强化倒计时，超时随机后展示具体分配结果。

## 8. 战斗 HUD

### 8.1 信息优先级

始终可见：

1. 是否轮到我、剩余时间、六个合法行动与实际金额；
2. 本人两张暗令、五张公共牌、主池/边池；
3. 本人气血/能量/牌型/胜算，其他五人的气血、能量、当前行动；
4. 回合、血祭、庄家、当前行动者和网络状态。

按需查看：

- 完整战报；
- AI 建议理由与指标；
- 英雄完整技能；
- 多级边池明细；
- 音乐、音效、动效、退出等设置。

### 8.2 横屏主布局（844×390 基准）

~~~text
┌ 菜单 │ R3/12 │ 血祭20/40 │ 网络 │ 战报 │ 设置 ┐ 36
│                 对手4   对手3   对手2                  │
│ 对手5       主池420  [天时][天时][天时][地利][人和] 对手1 │ 约228
│                 最近行动 / 边池摘要                   │
├ 我方状态/技能 │ 两张暗令/牌型 │ 建议/计时 │ 3×2行动区 ┤ 105
└─────────────────────── 底部安全区 ─────────────────────┘
~~~

布局规格：

- 顶栏 36–40px，只保留战斗状态，不显示大标题；
- 对手卡 68×76px 左右：头像、短名、气血、能量、当轮投入；
- 公共牌宽 clamp(48px, 7vw, 66px)，比例约 1:1.4，间距 4–7px；
- 本人暗令 60–72px 宽，可轻微叠放；
- 底部操作坞固定，并计入 safe-area-inset-bottom；
- 主池常显；多级边池折叠为“边池×N”，点击打开明细；
- 当前行动者用外框计时环 + “行动中”文字；退避、决死、阵亡同时使用图标与文字。

### 8.3 紧凑横屏布局（568×320 基准）

紧凑横屏沿用同一空间化六人桌，不切换为另一套结构：

- 顶栏压缩至 32px，合并次要状态，只保留回合、血祭、网络、战报和设置；
- 对手卡缩至约 52×58px，使用头像、气血数字、能量和行动标签，不显示完整立绘；
- 公共牌宽 42–48px，五张保持同排，牌点与花色必须完整可辨；
- 本人暗令宽 50–56px，牌型与胜算合并为一行；
- AI 建议仅保留单行摘要，完整理由进入抽屉；
- 六个行动按钮保持固定 3×2，不合并、不隐藏；
- 去除装饰台词、持续阴影和非必要动效，为操作与安全区让位。

### 8.4 竖屏阻断层

竖屏不渲染游戏布局，只显示全屏旋转引导：

- 品牌标识和横置手机动画；
- 主文案“请将手机横置”；
- 联机战斗中附加“当前行动计时仍在继续”；
- 支持方向锁时提供“再次尝试横屏”按钮；
- 不提供任何游戏行动、房间、选将或设置入口；
- 遮罩层 z-index 高于弹窗、特效、声音和全部业务页面；遮罩出现时给业务根节点设置 inert 与 aria-hidden，焦点移入引导层，拦截 pointer/touch/keyboard 输入。

### 8.5 对手状态卡

常显字段：头像、姓名/座位、气血、能量、当前投入、最近行动。

状态表达：

- 庄家：角标“庄”；
- 当前行动：金色计时环 + 行动中文字；
- 弱网/离线托管：网络图标 + 文字；
- 退避：灰色遮罩 + “退避”；
- 决死：红色边框 + “决死”；
- 阵亡：灰阶 + “第 N 回合阵亡”。

点击后展示公开信息与技能说明，绝不能泄露暗令或私密技能结果。

## 9. 行动交互

行动区保持固定 3×2 布局：

| 第一行 | 第一行 | 第一行 |
|---|---|---|
| 退避 | 静观 / 应战 X | 决死 |

| 第二行 | 第二行 | 第二行 |
|---|---|---|
| 佯攻 X | 强攻 X | 猛攻 X |

规范：

- 每个按钮同时显示动作和实际气血金额；
- 不合法操作保持原位禁用，点击信息图标可查看禁用原因；
- 静观/应战是视觉主按钮，决死为危险按钮；
- 决死采用二次确认：第一次点击后按钮变为“确认决死”，3 秒未确认恢复；不能只依赖长按；
- 当前可免费静观时点击退避，提示“可免费静观，仍要退避？”；
- 点击任何行动后立即进入“提交中”，锁定重复点击，但不在客户端乐观修改气血或池额；
- 服务端确认后播放行动反馈；拒绝时恢复按钮并给出明确原因；
- 每条行动命令携带 clientActionId 与 expectedSeq，服务端幂等处理；
- 旋转、后台恢复和重复网络包不能导致重复下注。

计时：

- 使用服务端 actionDeadline 和 serverNow 计算；
- 30–10 秒金色，10–5 秒橙色，5 秒内红色；不做高频闪烁；
- 延时按钮显示“+30 秒 · 1⚡”，提交后等待服务器刷新截止时间；
- 切后台或恢复时立即重新校时，客户端本地计时不得成为裁决依据。

## 10. 技能交互

技能按钮始终展示：技能名、能量成本、可用/不可用状态。不可用时展示最关键原因，例如“需含玄武♠”或“能量不足”。

技能选择使用横屏右侧抽屉；选项较多时使用底部抽屉：

- 有明确标题、步骤、取消、上一步和确认；
- 不再只靠点击遮罩取消；
- 抽屉不超过可视宽度 46% 或可视高度 72%，内容独立滚动；
- 倒计时始终可见，超时后关闭技能态并展示自动行动结果；
- 提交前目标失效时，服务端返回错误并刷新候选，不静默失败。

必须覆盖当前全部技能输入类型：

- 无额外输入；
- 选择目标玩家；
- 普通单选预测；
- 目标 + 单选的多步骤输入；
- 选择本人某张暗令；
- 选择可复制被动来源。

本人暗令在普通状态只用于查看；进入需要选牌的技能态后才出现选择框和“取消 / 确认”。

## 11. 战报、AI 建议与辅助信息

### 11.1 战报

- 顶栏按钮打开右侧抽屉，宽度不超过 min(420px, 46vw)；
- 分为全部、行动、技能、结算；
- 新事件显示未读点，打开后定位到最新；
- 文本允许选择和复制；
- 抽屉打开时不暂停比赛，倒计时固定可见。

### 11.2 AI 建议

- 默认只显示一行摘要：“建议：应战 80 · 64%”；
- 点击后查看主建议、备选、理由和 SPR/赔率等指标；
- 开关移入设置并记忆；
- 明确标注“近似建议”，不能暗示保证胜率；
- 计算放入 Web Worker，并按决策状态缓存，避免阻塞主线程。

### 11.3 边池

- 主池常显；一个边池时直接显示金额；多个时显示“边池×N”；
- 点击明细展示每个池的金额、参与者和结算结果；
- 本人临时参考池只在轮到本人时出现，避免与真实主/边池混淆。

## 12. 结算页

结算采用横屏左右结构：左侧展示本人名次、英雄和状态，右侧展示六人排名；短横屏时两侧内容独立滚动，主 CTA 固定在右下安全区内。

必须展示：

- 本人名次与高亮；
- 存活气血或阵亡回合；
- 六人完整排名；
- 单机“再来一局 / 返回选将”；
- 联机“返回队伍”。

主 CTA 不得因短屏、大字体或浏览器底栏而不可达。战斗重连后若对局已结束，应恢复到同一结算结果。

## 13. 弱网、断线与恢复

### 13.1 用户界面

状态分为：良好、弱网、重连中、离线托管。

- 战斗中断线时保留原战场 DOM，在上方显示轻量状态层；
- 不替换成空白“请刷新”页面；
- 重连成功展示“已恢复至最新进度”；
- 重连期间可以查看现有信息，但行动区明确锁定；
- 超过保留期后展示“座位已进入托管 / 返回首页”，不能假装仍可恢复。

### 13.2 协议要求

- 首次连接返回 sessionId 与一次性 resumeToken；token 放在 sessionStorage，不写日志；
- 重连首条消息支持 resume，并携带最后收到的 seq；
- 服务端快照包含 seq、serverNow、actionDeadline、公开状态及只给本人的暗令；
- 服务端至少保留座位与私有状态 120 秒；token 成功使用后轮换；
- 重连采用 0、1、2、4、8 秒退避并加随机抖动；
- 心跳建议 10 秒一次，连续 3 次无响应判定断开；
- 对局仍按原行动截止时间裁决；网络断开后不得固定 1 秒即托管；
- 页面刷新、Wi-Fi/蜂窝切换、短时后台回收后都应恢复到原座位；
- 对局结束后仍可补发结算快照。

### 13.3 命令一致性

- 客户端命令含 clientActionId、expectedSeq；
- 服务端返回 ack 或 reject；
- 重复命令不重复扣除气血；
- 乱序消息按 seq 丢弃或请求快照；
- 暗令永远只在本人私有快照中出现。

## 14. 性能与资源预算

| 项目 | 上线预算 |
|---|---:|
| 首页冷启动传输量（不含用户主动音频） | ≤ 800KB |
| 首屏 LCP 图片 | ≤ 250KB |
| 16 英雄全部缩略图 | ≤ 1.2MB |
| 进入战斗新增资源 | ≤ 1.5MB |
| 移动图片解码常驻 | 建议 < 80MB |
| 页面总内存 | 建议 < 150MB |
| 主线程单任务 | < 50ms |

资源策略：

- 英雄列表使用约 256px AVIF/WebP 缩略图，单张建议 ≤50–75KB；
- 详情只加载当前英雄 640–768px 图片，单张建议 ≤120–180KB；
- 本局只加载六名参战英雄的大图；
- 使用 img、srcset、loading=lazy、decoding=async，不再一次创建 16 个大图背景；
- 牌背和背景按实际显示尺寸输出 1x/2x；
- BGM 在首次用户手势后仅加载当前曲，不预加载整个音乐池；
- 页面后台暂停音乐与非必要动画；
- HTML 采用 network-first，带内容哈希的资源长期缓存；
- Service Worker 只预缓存壳和关键 UI，不缓存私有对局快照；
- 生产启用 Brotli/Gzip、内容哈希和版本清单，避免新旧模块混用。

体验指标：

- 中端 Android、Fast 4G：LCP p75 ≤2.5s；
- INP p75 ≤200ms；
- CLS ≤0.1；
- 战斗主要交互目标 50–60fps；
- 断网恢复不出现整页白屏。

## 15. 无障碍、音频与触觉

- 所有可点击元素使用 button 或等价语义，提供 focus-visible；
- 弹层使用 role=dialog、aria-modal、标题关联、焦点圈定与关闭后焦点恢复；
- 当前决策、网络变化和结算使用节流后的 aria-live；倒计时不要每帧朗读；
- 卡牌提供可读名称，例如“玄武 A”“暗令未揭示”；
- 状态不能只用红绿区分，必须同时使用文字、图标或形状；
- 输入框、战报允许选择文字，移除全局 user-select:none 的误伤；
- 不禁用浏览器缩放；200% 文本缩放下核心流程仍可完成；
- 音乐、音效、震动分别控制；重要反馈不能只靠声音或震动；
- 低电量/减少动态效果时自动降级高成本特效。

## 16. 安全与隐私

- 玩家名、队伍名、toast 和任何服务端文本使用 textContent 或统一转义，不直接进入 innerHTML；
- 服务端限制命令大小、频率、字段类型与字符串长度，并做 Unicode 规范化；
- 生产只允许 HTTPS/WSS，校验 WebSocket Origin；
- 设置 CSP：脚本、连接、图片、音频均采用明确白名单；
- resumeToken 只保存在 sessionStorage，成功恢复后轮换，不进入 URL、日志或埋点；
- 暗令、技能私密结果不得进入公共快照、战报、错误上报或分析事件；
- 错误日志使用 requestId / sessionHash，不上传玩家输入原文。

## 17. 状态与异常矩阵

| 场景 | 界面反馈 | 恢复动作 |
|---|---|---|
| 首页资源失败 | 单项失败与原因 | 重试该资源 / 低画质继续 |
| WebSocket 首连失败 | 错误页，不清空首页 | 重试 / 返回首页 |
| 战斗弱网 | 顶栏弱网图标 | 自动恢复，无阻断弹窗 |
| 战斗断线 | 原战场上的重连层 | 自动重连 / 超时托管 |
| 行动提交慢 | 按钮显示提交中 | 等待 ack，禁止重复 |
| 行动被拒绝 | 明确原因，刷新合法项 | 重新决策 |
| 英雄被抢 | 卡片更新占用者 | 保留详情，选择其他英雄 |
| 技能目标失效 | Sheet 内联错误 | 刷新候选目标 |
| 浏览器变为竖屏 | 全屏旋转阻断层；联机提示计时继续 | 横置后恢复原状态与草稿 |
| 页面恢复 | 短暂同步提示 | 拉取快照并校时 |
| 新版本发布 | 非战斗节点提示 | 用户确认后刷新 |
| 对局已结束 | 恢复结算快照 | 返回队伍 / 再来一局 |

## 19. 上线验收

### 19.1 P0 必过

- 所有目标横屏尺寸下，五张公共牌、两张暗令、倒计时与六个行动无需页面滚动即可使用；
- 所有竖屏尺寸都只能看到旋转阻断层，DOM 中不可聚焦或点击游戏控件；
- 支持方向锁的浏览器在用户点击后进入横屏；不支持时，手动横置后可以自动放行；
- 刘海、圆角、Safari 地址栏收起/展开、Home Indicator 不遮挡按钮；
- 六类行动只执行一次，延迟 ack、重复包、乱序包不重复扣血；
- 服务端与客户端倒计时误差不超过 1 秒；
- 300ms RTT、5% 丢包下仍能完成行动，并明确显示 pending；
- Wi-Fi 切蜂窝、断网 10/30/90 秒、刷新后在保留期内恢复原座位和暗令；
- 房间满员、房主断线、英雄抢占、选将超时均有确定结果；
- 所有技能输入类型可取消、回退、确认，目标失效有反馈；
- 主池、多级边池、平分、净收益与服务端一致；
- 首页、选将、战斗满足资源和性能预算；
- 用户/服务端文本通过 XSS 用例，暗令不出现在公共协议与日志。

### 19.2 兼容与可达性

- iOS Safari、Android Chrome、微信内置浏览器真机通过；
- 前后台切换、锁屏恢复、来电中断、横竖屏切换、软键盘均不丢状态；
- 200% 文本缩放、减少动态效果、静音模式仍能完成核心流程；
- VoiceOver/TalkBack 可读出回合、本人暗令、主池、行动与金额；
- 低内存设备连续完成两局，不发生持续内存增长或页面回收。

### 19.3 游戏回归

- 下盲、四轮行动、公共牌揭示；
- 退避、静观、应战、三档进攻、决死；
- 无争夺获池、亮招、主池/多级边池、平分；
- 16 英雄主动/被动与全部选择输入；
- 真人阵亡、12 回合结束、单机结算、联机战后回房；
- 暗令仅本人、授权技能、决死公开或亮招时可见。

## 21. 评审建议

本方案建议先确认三个决策，再进入高保真与开发：

1. 已确认全流程横屏专用，竖屏只显示不可操作的旋转阻断层；
2. 本期只做当前功能手机化，不把匹配/邀请/分享并入范围；
3. 将断线恢复与资源压缩列为上线 P0，而不是后续优化。

下一阶段应先产出横屏门禁、横屏首页、横屏选将、标准/紧凑横屏战斗和技能抽屉关键高保真稿，再扩展全状态页面。
